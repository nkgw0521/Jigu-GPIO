# NUCLEO-F303K8

## 端子配置と配線

| ボード上の表記・コネクター | MCU端子 | ファームウェアの機能 |
|-----|-----|----------|
| D9 / CN3 12番端子 | PA8 (FT) | トリガー／PWM出力（TIM1_CH1）、3.3 V出力 |
| D11 / CN3 14番端子 | PB5 (FT) | 外部パルスカウンター（TIM3_CH2）、ソフトウェアで32ビットに拡張 |
| D2 / CN3 5番端子 | PA12 (FT) | GPIO1 |
| D13 / CN4 15番端子 | PB3 | オンボードLED（LD3）、`SYSTem:LED` の機能を復元済み |
| ST-LINK VCP（SB2開放時はA7） | PA2 | USART2 TX |
| ST-LINK VCP（Nanoヘッダーには未接続） | PA15 | USART2 RX |
| GND / CN3 4番端子またはCN4 2番端子 | GND | 信号グラウンド |

- トリガー先またはオシロスコープを **D9（PA8）** と **GND** に接続してください。
- `PWM:Counter?` で出力数を確認する場合は、**D9（PA8）とD11（PB5）をジャンパー接続**してください。`PWM:Numbers` による有限パルス出力はPWMタイマー内部の割り込みを使用するため、このジャンパーは外部でパルスを計測する場合だけ必要です。
- **SB15は接続したままで使用できます**。D13/PB3はLED出力に戻しており、カウンター入力には使用しません。
- D11/PB5とD2/PA12は5 V耐性のあるデジタル入力です。外部から5 V信号を入力する際は、ボードに給電し、GPIO入力モード・プル抵抗なしで使用してください。プッシュプル出力は3.3 Vです。以前使用していたA1/PA1とA5/PA6は、これらの機能では使用しません。
- TIM3の16ビットカウンターを更新割り込みで符号なし32ビットに拡張しています（0～4,294,967,295、その後0に戻ります）。読み取り時は未処理のオーバーフローも反映し、書き込み・リセット時は上位・下位の両方を更新します。停止・開始をまたいでカウント値を保持します。入力65,536パルスごとに少なくとも1回は割り込み処理が必要です。割り込みが処理できない間に複数回オーバーフローした場合は復元できません。実機で信頼性を確保できる最大入力レートは未測定です。
- ST-LINK USB仮想COMで制御します。通信条件は **115200 baud、8N1、フロー制御なし**、コマンドの終端はLFです。VCPはD1/D0ではなく、PA2/PA15とSB2/SB3を使用します。

参考資料：[ST DS9866：端子機能とタイマー機能](https://www.st.com/resource/en/datasheet/stm32f303k8.pdf)、[ST UM1956：表12とはんだブリッジ](https://www.st.com/resource/en/user_manual/dm00231744-stm32-nucleo32-boards-mb1180-stmicroelectronics.pdf)。

## TIM3カウンターの拡張

- D11/PB5はAF2、TIM3_CH2、外部クロックモード1、TI2FP2を使用します。TIM3はPSC=0、ARR=65535とし、NVICでTIM3更新割り込みを有効にしています。
- `Core/Src/counter32.c` で上位16ビットを保持し、TIM3更新コールバックごとに65536を加算します。演算結果は2^32を法として折り返します。
- `counter32_get()` は割り込みをマスクし、下位16ビットを読み取って未処理のUIFを確認します。読み取り前または読み取り中に折り返しが発生した場合は、CNTを再読して未処理の桁上がりを反映します。UIFはISR用にセットしたままにするため、繰り返し読み取っても二重カウントしません。
- `counter32_set()` はカウンターを短時間停止し、上位・下位の値を更新して、古いUIFとNVICの保留状態をクリアします。明示的な設定・リセット中の入力エッジは無視します。動作状態と呼び出し元の割り込みマスクは保持します。
- 開始・停止時は未処理のオーバーフローを一度だけ反映し、カウント値を保持します。停止時は、キャプチャーチャンネルが有効な場合でもCENを明示的にクリアします。
- `PWM:Counter` と `PWM:Counter?`、およびPWMデバッグスナップショット内のカウンター項目は拡張後の値を使用します。F303は現在TIM3を使用していますが、プロトコル互換性のため従来の `T2...` デバッグラベルを維持しています。
- パルス完了を検出する入力エッジは、従来どおりPWM極性で選択します。アクティブLowでは立ち上がり、アクティブHighでは立ち下がりです。
- この拡張はカウント範囲を広げるものであり、割り込み処理は引き続き必要です。UIFが記録できる未処理オーバーフローは1回分だけです。入力周波数をfとすると、オーバーフローの処理間隔は65536/f秒未満にする必要があります。実際の高速入力時の動作は実機未検証です。

## アプリケーションとプロジェクトの統合

- `main.c` はGPIO、DMA1、TIM1、TIM3、USART2の初期化後に `app_main()` を呼び出します。
- `tim.c`/`tim.h` でPWM用のTIM1_CH1とカウンター用のTIM3_CH2を設定します。初期化で発生したTIM3のUIFは、カウント開始前にクリアします。
- `stm32f3xx_it.c` はTIM3割り込みをHALに渡します。共通の周期コールバックは、F303のソフトウェア拡張対象でのみ `counter32_on_overflow()` を呼び出します。
- `App/Inc/board_config.h` はF303K8の場合だけ `htim3` と `PWM_COUNTER_SOFTWARE_EXTENSION` を選択します。既存ボードのカウンター処理は従来どおりです。
- `App/Inc/gpio.h` はF303の場合だけGPIO1をPA12に割り当てます。`App/Src/gpio.c` は通常のLED書き込み処理を復元し、F303の `Core/Src/gpio.c` はPB3をLED出力に設定します。
- `NUCLEO-F303K8.ioc` にTIM3/PB5、TIM3更新割り込み、GPIO1のPA12、LEDのPB3を記録しています。PWMは引き続きPA8/TIM1_CH1です。
- USART2は循環受信DMA1_Channel6とUART/DMA割り込みを使用します。クロックは内部HSI 8 MHz / 2、PLL ×16、SYSCLK 64 MHzです。APB1は32 MHz、APB2は64 MHzです。TIM1の初期PSC=63により、初期設定の1 kHzを維持します。TIM HALドライバーはSTM32CubeF3 V1.11.6のものです。
- `App` と `libscpi` は、それぞれ `PARENT-2-PROJECT_LOC/App` と `PARENT-2-PROJECT_LOC/libscpi` にある共通リソースへのリンクです。Debug/Releaseともに両方をコンパイルし、`BOARD_NUCLEO_F303K8` を定義します。リンカースクリプトは `../STM32F303K8TX_FLASH.ld` を使用します。

## シリアル通信の起動修正と実機検証（2026-11-19）

以前のファームウェアはHSEバイパス（外部8 MHz）を選択していましたが、ボード側に使用可能なHSEクロックがありませんでした。RCC_CRは0x00056283（HSE有効、未準備）、RCC_CFGRは0で、CPUは割り込み禁止のエラーループ内にあり、USART2のCR1/BRRも0のままでした。COM16は開けても、データは返りませんでした。

F303だけを対象に、`main.c` とIOCのクロック設定をHSI/2 ×16 = 64 MHzに変更しました。TIM1のプリスケーラーは63、CubeIDEのデバッグ用CPUクロックは64 MHzです。USART2は固定のPCLK1クロック（32 MHz）を使用し、115200 baudで動作します。はんだブリッジの変更は不要です。PWMの周波数・パルス幅の計算は、従来から実行時のAPBタイマークロックを使用しています。タイミング精度は内部RC発振器に依存し、波形精度は未測定です。

ST-LINK `0671FF555185754867192242`（COM16）でReleaseの書き込みとFlash検証に成功しました。起動時のRCC_CR=0x03006283とRCC_CFGR=0x0038040AでPLL起動を確認し、USART2も初期化されました。

115200/8N1、フロー制御なし、終端LFで実機のシリアル通信を確認しました。

- `*IDN?` -> `MANUFACTURE,INSTR2013,0,01-02`
- `*OPC?` -> `1`
- `PWM:Counter?` -> `0`（完全なコマンド名はCountではなくCounterです）。
- 65535、65536、305419896、4294967295の設定・読み取りが一致しました。従来のSCPI書き込みマスクはF303だけで削除し、既存ボードは従来の動作を維持しています。
- `SYSTem:LED 0` と `SYSTem:LED 1` の両方で、GPIOBのODRビット3が期待どおり変化しました。
- `SYSTem:ERRor?` -> `0,"No error"`。

検証後はカウンターを0に戻し、LEDを点灯、PWMを停止した状態にしました。端末ソフトから開けるように、COM16を閉じました。

## PWMループバック検証と共通の単発パルス修正（2026-11-19）

配線はD9/PA8のPWM出力からD11/PB5のカウンター入力、シリアルはCOM16、内部クロックは64 MHzです。最終版の共通実装を、このF303に書き込んでいます。

初期試験では、TIM1を無効にするとPA8が駆動されなくなり、有限パルス出力の停止後も、動作を続けるカウンターにエッジが加算されることが分かりました。共通ポート実装は、PWMを無効にする前にGPIOへ非アクティブレベルを設定し、開始前にAFモードへ戻すようにしました。`PWM_OUTPUT_GPIO_PORT`/`PWM_OUTPUT_GPIO_PIN` を使用しており、アイドル状態や単発出力にF303固有の分岐はありません。

従来は単発出力の要求でも更新イベントを待つため、2発出力していました。共通ジェネレーターでは、最初のパルス前に比較一致による停止を準備します。UGで実際のパルス幅をロードした後、ポート実装がCCRプリロードに0を書き込むため、ISRが遅れても2発目のアクティブパルスは始まりません。この修正は全対応ボードに適用されます。カウンター拡張は引き続きボードの機能に応じて選択します。

最終的な実機結果は、リポジトリルートからの相対パス `tests/f303_counter32/hardware-loopback-result.json` に保存しています。確認項目は次のとおりです。

- アクティブLowとアクティブHigh、1 kHz／設定値100 usで、1・2・3・10発の要求にループバックのカウント値が正確に一致しました。150 ms待機後もカウントは増加しませんでした。
- 10 kHz／設定値20 usで、65,535・65,536・65,537・131,079発を出力し、カウントを繰り返し読み取りながら、16ビットのオーバーフローが1回および複数回発生する場合を検証しました。
- アクティブLowで70,000発を出力し、最終カウントが安定していることを確認しました。
- 4,294,967,280から32発を出力し、2^32を法とした期待値16を確認しました。
- 65,530から、リセットせずに10発の出力を2回行い、期待値65,540、65,550を順に確認しました。

これらは実際のループバックによるエッジ数であり、独立した時間基準による波形測定ではありません。この配線では、絶対周波数、最初のパルス幅、ジッター、電圧レベル、5 V耐性を検証できません。記載した周波数とパルス幅は設定値です。

共通のホスト統合テストは、CH1/PA8とCH2/PB14のタイマーモデルを使用して、実際のジェネレーターとSTM32ポートをコンパイルします。両極性、最初のパルス幅のプリロード、単発・複数・連続パルス、繰り返し開始、待機時のGPIOモードを確認します。`python tests/pwm_single_pulse/run.py --compiler gcc` を実行してください。

5ボードすべてでDebug/Release構成のビルドを確認しました。他ボードは一時コピー内でビルドし、プロジェクトファイルの変更や実機への書き込みは行っていません。L432KC、L053R8、DiscoveryのリンカーはRWX LOADセグメントの警告を出します。L073RZとF303のビルドは警告なしです。他ボードでは、共通修正の実機検証が引き続き必要です。

## 同期化前の最初のパルス幅の検証（2026-11-19）

D9–D11の配線を使用し、ファームウェアの一時コピーでTIM3をフリーラン動作する64 MHzの入力キャプチャータイマーに設定しました。IC1の間接TI2入力でアクティブ開始エッジ、IC2の直接TI2入力で非アクティブに戻る終了エッジを記録しました。キャプチャー割り込みは無効にし、パルス中に計測用コードを実行せず、ハードウェアでタイムスタンプを保持しました。その後、通常の製品用ファームウェアを復元して検証しました。製品用ソースは変更していません。

両極性、指定幅1/2/5/10/20/100/500 us、各3回の開始（42サンプル）で、最初のパルスは常に指定値より **29タイマーティック（公称0.453125 us）長い** 結果でした。例：1 us -> 1.453125 us、10 us -> 10.453125 us、100 us -> 100.453125 us。両方のエッジを取得でき、オーバーキャプチャーはありませんでした。

HALはCENを設定する前に出力チャンネルとメイン出力を有効にします。その間もCNTは0のため、最初のアクティブパルスが長くなります。CCRシャドーを正しくロードし、1発で停止しても、この開始遅延は解消しません。これはコミット3ca43f8での修正前の結果です。以下の共通同期開始処理で、余分なティックを解消しました。

us値は、共通のHSIから生成した公称64 MHzを基準にしており、絶対時間を独立に校正するものではありません。計測用ファームウェアは開始シーケンス前に呼び出しを追加し、リンク時の配置も変えるため、修正後にはサイクル単位の正確な遅延を再確認する必要があります。生のキャプチャーデータと測定方法は `tests/f303_counter32/first-pulse-width-result.json` に記録しています。

## 共通の同期開始処理と最終検証（2026-11-19）

製品用の開始シーケンスは全ボード共通です。F303固有の開始・パルス幅処理の分岐は追加していません。

1. PRIMASKとURSを保存し、タイマーの更新・比較一致割り込みを無効にします。ソフトウェアUGをPWM周期としてカウントしないようにURSを設定します。
2. 指定幅をプリロードに保持しつつ、実際に使用するCCRとシャドーCCRに0をロードします。この非アクティブ波形の状態で出力チャンネルとタイマーを有効にします。
3. 非アクティブな準備期間に残ったフラグをクリアし、UGを発生させます。同じハードウェアイベントでCNTとプリスケーラーをリセットし、指定幅をロードすることで、最初のアクティブエッジから設定どおりの時間を確保します。
4. 単発出力では、次周期のCCRプリロードを0にし、比較一致による停止を有効にします。実際のパルスがすでに終了していても、そのCCフラグを保持します。複数・連続出力では更新回数のカウントを有効にします。URSと呼び出し元の割り込みマスクを復元します。

ジェネレーターは出力有効化前にSCPIの開始状態を設定し、SCPIコマンドは正常終了時にその状態を上書きしないようにしました。これにより、終了済みの1 usパルスが出力中と報告されることを防ぎます。開始に失敗した場合は両方のタイマーを停止し、端子を非アクティブレベルのGPIO出力へ戻します。

一時的な検証用ファームウェアで、D11のTIM3 IC1（間接TI2）とIC2（直接TI2）を設定し、最初のアクティブ・非アクティブエッジのタイムスタンプを取得しました。終了エッジのコールバックは、両方のハードウェアタイムスタンプが保持された後でキャプチャーを停止するため、後続のパルスが最初のパルス幅を上書きしません。2つのエッジ間でキャプチャーISRは実行されません。この診断コードは製品用ファームウェアには含まれていません。ソースは参考用に `tests/f303_counter32/width_probe/` に保存しています。

**最初のパルス幅は84/84件すべてで、指定したタイマーティック数と正確に一致しました。** 条件は、要求パルス数1発・3発、両極性、パルス幅1/2/5/10/20/100/500 us、各条件で連続3回の開始です。公称64 MHzでは、それぞれ64/128/320/640/1280/6400/32000ティックです。従来の余分な29ティックは解消しました。生の結果と、製品用ソースを正規化したハッシュは `tests/f303_counter32/synchronized-first-pulse-width.json` に記録しています。

これらの測定は、独立して校正した時間基準ではなく、MCU内で共通のHSI由来クロックを使用しています。加算されていた開始遅延の解消は確認できますが、秒単位の絶対精度は引き続き発振器精度とキャプチャー分解能に依存します。他ボードはDebug/Releaseビルドと共通のホストモデルで確認済みですが、実機で最初のパルス幅は測定していません。

通常の製品用ファームウェアを復元し、F303への書き込みとFlash検証を完了しています。`tests/f303_counter32/synchronized-loopback-regression.json` に、有限・短パルスのカウント、停止後の安定性、65,536および複数回オーバーフローの境界、2^32を法とした折り返し、再開をまたぐカウント保持、1 us単発の繰り返し、連続出力・SYNC・停止の確認結果を記録しています。完了時はPWMを停止し、カウントを0、設定を50 Hz / 1 us / アクティブHigh / Numbers 0 / SYNC 0に戻し、COM16を解放しました。
